# 검증 결과와 기능 범위

검증일: 2026-09-28. 버전: 0.1.0. 개발 호스트: Windows x64 / .NET SDK 10.0.401 / Docker Desktop Linux 컨테이너.

| 범위 | 결과 |

| 최종 자동 테스트 | 26개 통과, 실패/건너뜀 0개 |
| SFTP / SCP / FTP / WebDAV / S3 | 실제 프로토콜로 업로드·다운로드 바이트 일치, 한글/공백/따옴표/$ 이름, 이름 변경, 삭제 |
| 동기화 | 같은 내용 재전송 방지, 변경 적용, 적용 후 차이 없음, 오래된 미리보기 거부 |
| 이어받기 | SFTP/FTP 부분 전송 중단 후 재연결·완료, 원본 변경 시 재개 거부 |
| SSH / 권한 | 틀린 호스트 키 거부, SFTP/SCP 권한 변경 및 덮어쓰기 시 보존, SFTP 특수 비트 |
| 비밀 저장소 / 파일 편집 | 마스터 암호 검증, 암호 평문 미저장, SHA-256 변경 감지 |

| UI | Chromium에서 SFTP 연결, 호스트 키 확인, 업로드, 더블 클릭 편집/저장, 동기화 6개 변경 미리보기·적용; 콘솔 오류 0 |
| Windows 네이티브 | 최종 자체 포함 실행 파일에서 Photino 창 및 WebView2 프로세스 생성, 창 닫기 후 종료 |
| Linux 네이티브 | Ubuntu 24.04 Docker/Xvfb에서 Photino 창 실행 및 종료 신호 처리; 기본 테스트 17개 통과, 선택 테스트 4종 건너뜀 |
| Linux 패키징 | vpk로 AppImage 및 전체 업데이트 패키지 생성; 생성한 AppImage 자체 실행/종료 성공 |
| macOS | 최종 소스의 osx-arm64 자체 포함 교차 빌드 성공 |
| 배포 서버 이미지 | 비루트 ASP.NET Core 컨테이너 이미지 빌드 성공 |

프로토콜 테스트는 OpenSSH, pyftpdlib, WsgiDAV, S3 호환 moto를 사용했습니다. AWS 실제 계정, 모든 FTP/SSH 장비와의 호환성을 검증한 결과는 아닙니다. Linux GUI 실행 검사는 가상 디스플레이 환경의 시작/종료 검사이며 실제 데스크톱 사용성 검증을 대신하지 않습니다.

최종 산출물은 `dist/`에 있습니다. `artifacts/`에는 개발 중 생성한 이전 패키지와 테스트 자료가 남아 있으므로 배포에는 `dist/`를 사용하세요. 테스트 원본 결과는 `tests/Portway.Tests/TestResults/verified.trx`, UI 화면은 `output/playwright/workspace.png`에 있습니다.

## 아직 검증하지 않은 항목

- macOS 실기기 실행, macOS vpk 설치/제거 및 Apple 서명·공증
- Windows/Linux ARM64 실행, macOS Intel 실행
- Windows Setup 설치/제거 및 실제 설치판의 버전 업그레이드→재시작 전체 흐름
- 실제 신뢰된 인증서를 사용하는 FTPS/WebDAV HTTPS 서버와의 상호 운용
- 장시간 전송, 대용량 S3 멀티파트 복사, 네트워크 장애/디스크 부족/강제 종료의 모든 조합
- 공개 도메인 배포, GitHub Actions 원격 실행, 실제 코드 서명

위 기능의 코드/구성은 포함되어 있지만 검증 완료로 표시하지 않습니다. 현재 생성한 Windows 설치 파일은 서명되지 않았습니다.

## WinSCP와의 차이점

이 버전을 WinSCP의 완전한 기능 동등 제품으로 간주해서는 안 됩니다. 주요 파일 전송 워크플로를 제공하는 독립 구현이며 아래 기능은 없거나 제한됩니다.

| 영역 | 현재 범위 |
|---|---|
| 인증/연결 | 암호와 SSH.NET 지원 개인 키. SSH Agent/Pageant, PPK 변환, SSH 터널/점프 호스트, 프록시 UI, 대화형 MFA 없음 |
| SCP | 원격 POSIX 셸과 GNU find 필요. SCP 전송에 SFTP는 필요하지 않지만 BSD/Windows SSH 셸까지 범용 지원하지 않음 |
| 전송 큐 | 메모리에 저장. 앱 종료 후 큐/재개 정보 복원 없음. 이어받기는 동일 실행 중 SFTP/FTP 작업 재시도 범위 |
| 중단 파일 | `.portway-part-*`, 실패한 편집 임시 파일, 일부 백업이 남을 수 있음. 자동 정리/복구 관리 화면 없음 |
| 파일 교체 | 임시 파일/백업 이름 변경으로 오류 복구. 원격 프로토콜별 원자성은 다름. S3 이동은 복사 후 삭제 |
| 충돌 보호 | 전송 중 크기/수정 시각 변화 검사, 편집/동기화 해시 검사. 다른 프로그램의 모든 동시 변경을 원자적으로 차단하지는 못함 |
| 메타데이터 | 원격 기존 권한을 서버에서 제공하면 보존. 소유자/ACL/xattr 전반과 모든 타임스탬프 보존은 없음 |
| 동기화 | 수동 미리보기/적용. 20,000개 항목, 깊이 64 제한. 폴더 전체 트랜잭션/롤백, 실시간 감시, 파일 마스크 없음 |
| 링크 | 재귀 전송에서 심볼릭 링크를 자동 추적하지 않음. 링크 생성/정밀 관리 없음 |
| 편집 | 2 MiB 이하 UTF-8 텍스트. 외부 편집기 연동/감시, 인코딩 선택, 바이너리 편집 없음 |
| 셸 | 30초 제한 단일 SSH 명령. 대화형 PTY 터미널 없음 |
| S3 | 한 버킷의 파일 작업. 특수 객체 키 전체 표현, 버전/ACL/스토리지 클래스 관리, 별도 세션 토큰 입력 UI 없음 |
| FTP | 수동 연결 모드 기본. 서버가 권한 정보를 제공하지 않으면 표시/보존 불가. 고급 전송 모드 설정 UI 없음 |
| 자동화 | 앱의 로컬 REST API 존재. WinSCP 스크립트/.NET 자동화 API의 호환 계층 없음 |
| 가져오기 | WinSCP INI 연결 설정. 기존 저장 암호 복호화, 레지스트리 직접 가져오기, 전체 작업 공간 복원 없음 |
| 배포 운영 | 단일 인스턴스 파일 저장소. 관리자 계정/SSO, 감사 이력 DB, 객체 스토리지, 다중 서버 조정, 자동 롤백 없음 |

실서비스 파일에 적용하기 전 해당 서버의 인증 방식과 필요한 고급 기능이 이 범위에 맞는지 확인하고, 작은 테스트 디렉터리에서 전송 및 복구 흐름을 검증하세요.
