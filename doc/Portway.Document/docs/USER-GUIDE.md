# Portway 사용자 가이드

이 문서는 **Portway 0.3.9**의 실제 화면과 동작을 기준으로 합니다. Portway는 웹 UI를 사용하는 데스크톱 파일 전송 앱입니다. 설치한 컴퓨터의 파일과 원격 서버 사이에서 작업합니다.

처음 사용하는 경우 **설치 → 첫 연결 → 파일 전송** 순서로 진행하세요. 개발 환경과 배포 서버 운영은 [개발자 가이드](DEVELOPER-GUIDE.md)를 참고하세요.

## 1. 설치와 실행

다운로드 페이지에서 운영체제와 CPU 아키텍처가 일치하는 패키지를 선택합니다. `x64`는 Intel/AMD 64비트, `arm64`는 ARM 64비트입니다. 현재 이 저장소에서 생성하고 확인한 패키지는 다음과 같습니다.

| 환경 | 패키지와 확인 범위 |
| --- | --- |
| Windows x64 (0.3.9) | [설치 파일](../../../dist/releases/win-x64-stable/Portway-win-x64-stable-Setup.exe), [포터블 ZIP](../../../dist/releases/win-x64-stable/Portway-win-x64-stable-Portable.zip). 0.3.9 패키지·Folded Hover 메뉴·로고 정렬·체크박스 UI 검증. 설치·자동 업데이트·제거는 0.3.3 검증 기록 참고 |
| Linux x64 (0.3.1) | [AppImage](../../../dist/releases/linux-x64-0.3.1-stable/Portway-linux-x64-stable.AppImage). Ubuntu 24.04 기반 컨테이너에서 시작 및 프로토콜 검증 완료 |
| macOS | 대상 프로젝트와 패키징 구성이 준비되어 있습니다. 배포 가능한 Mac 설치 파일과 실제 Mac 실행 검증은 아직 제공하지 않습니다 |

위 링크는 현재 작업 공간의 산출물입니다. 소스만 내려받은 환경에는 파일이 없을 수 있습니다. 배포 운영자가 제공한 다운로드 페이지 또는 직접 빌드한 패키지를 사용하세요. 전체 산출물은 [README](../../../README.md)에서 확인할 수 있습니다.

### Windows

1. `Portway-win-x64-stable-Setup.exe`를 실행하고 설치를 마칩니다.
2. Portway를 실행합니다. WebView2 Runtime이 필요하며 설치 패키지에 이 의존성이 지정되어 있습니다.
3. 포터블 버전은 ZIP 전체를 한 폴더에 풀고 `Portway.exe`를 실행합니다. 실행 파일만 따로 옮기지 마세요.

현재 제공한 Windows 패키지는 코드 서명되지 않았습니다. 운영체제에서 게시자를 확인할 수 없다는 안내가 나올 수 있습니다. 다운로드 출처와 [SHA-256 목록](../../../dist/SHA256SUMS-0.3.9.txt)을 확인하세요. PowerShell에서 파일의 해시는 다음처럼 확인합니다.

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath './Portway-win-x64-stable-Setup.exe'
```

### Linux

그래픽 데스크톱 세션과 GTK 3, WebKitGTK 4.1, libnotify가 필요합니다. 다음은 검증에 사용한 Ubuntu 24.04 계열의 패키지 이름입니다. 다른 배포판에서는 해당 배포판의 동등한 패키지를 사용합니다.

```bash
sudo apt-get install libgtk-3-0 libwebkit2gtk-4.1-0 libnotify4 libfuse2t64
chmod +x ./Portway-linux-x64-stable.AppImage
./Portway-linux-x64-stable.AppImage
```

FUSE를 사용할 수 없으면 다음 실행 방식을 사용할 수 있습니다.

```bash
./Portway-linux-x64-stable.AppImage --appimage-extract-and-run
```

설치 패키지에는 .NET 런타임이 포함됩니다. 앱 사용에 Node.js나 .NET SDK는 필요하지 않습니다.

## 2. 화면 둘러보기

![라이트 테마의 파일 워크스페이스](images/workspace-light.png)

| 화면 영역 | 용도 |
| --- | --- |
| 왼쪽 사이드바 | 저장한 사이트, 전송 관리, 북마크, 설정 및 업데이트, 휴지통 복원 |
| 상단 연결 탭 | 여러 서버 연결 사이를 전환합니다. 닫기 버튼은 해당 연결을 종료합니다 |
| 왼쪽 파일 패널 | 내 컴퓨터의 파일과 폴더 |
| 오른쪽 파일 패널 | 로컬 작업 공간에서는 내 컴퓨터의 다른 폴더, 서버 탭에서는 해당 서버의 파일과 폴더 |
| 상단 도구 모음 | 로컬 탭은 오른쪽·왼쪽으로 복사, 서버 탭은 업로드·다운로드·외부 파일·외부 폴더·동기화·지속 동기화 버튼 그룹, SSH 명령 |
| 아래쪽 전송 큐 | 작업 상태, 오류, 일시정지, 이어하기 / 재시도 |

왼쪽 메뉴는 평소 아이콘만 표시합니다. 마우스를 올리면 **Folded Hover** 방식으로 메뉴 이름과 Portway 로고 텍스트가 펼쳐집니다. 포인터가 나가면 접히며 파일 패널의 위치는 유지됩니다. `Tab` 키로 메뉴에 진입해도 펼쳐지고, 각 아이콘에는 도구 설명이 있습니다. 저장된 사이트가 많으면 메뉴 안에서 스크롤하며 사이트 옆 **…**로 편집합니다. 마우스 올리기가 없는 터치 환경에서는 전체 메뉴를 표시합니다. [펼쳐진 메뉴 화면](images/sidebar-expanded.png)을 참고하세요.

폴더를 두 번 클릭하거나 경로 입력란에 경로를 입력해 이동합니다. 열 제목을 클릭하면 정렬합니다. 패널의 검색 입력은 현재 목록을 좁히는 데 사용하고, 하위 폴더까지 찾으려면 원격 파일 메뉴의 **하위 폴더 검색**을 사용합니다.

현재 개발 소스에서 **수정한 날짜**는 컴퓨터의 현지 시간 기준으로 `2025-07-13 오전 6:54`처럼 표시합니다. 원격 연결 후 하단 상태바에는 `1.1.1.207에 연결됨 · 접속 00:12:34`처럼 접속 경과 시간(시:분:초)을 함께 표시합니다. 연결마다 따로 계산하며 다른 탭을 보는 동안에도 경과 시간은 계속 누적됩니다. 로컬 작업 공간에서는 숨기고, 연결을 종료한 뒤 다시 연결하면 새로 계산합니다.

### 내 컴퓨터 안에서 복사·이동하기

현재 개발 소스의 **로컬 작업 공간** 탭은 양쪽 모두 **내 컴퓨터**를 표시합니다. 처음에는 홈 폴더를 열며, 양쪽 경로 입력란에서 원본과 대상 폴더를 각각 선택할 수 있습니다. 서버 연결 없이 사용할 수 있습니다.

- 왼쪽 항목을 선택하고 **오른쪽으로 복사**, 오른쪽 항목을 선택하고 **왼쪽으로 복사**를 누릅니다. 파일 목록에 포커스가 있을 때 `F5` 또는 우클릭 **반대 패널로 복사…**도 같은 동작을 합니다.
- 파일 이름을 반대 패널로 드래그하면 복사 창이 열립니다. 대상 패널의 폴더 위에 놓으면 그 폴더로 복사합니다. 여러 파일·폴더와 중첩·빈 폴더를 함께 전송할 수 있습니다.
- `F6` 또는 우클릭 **반대 패널로 이동…**은 이동 창을 엽니다. 성공한 파일만 원본에서 삭제하며, 건너뛴 파일과 실패한 파일은 유지합니다.
- 같은 이름의 파일은 건너뛰기·덮어쓰기·최신 파일만·다른 이름으로 보관 중 선택합니다. 작업은 전송 큐에서 일시정지·재시도하며, 앱 재시작 후에도 서버 연결 없이 이어할 수 있습니다. 파일 내용과 줄바꿈은 변환하지 않습니다.

같은 경로로 전송하거나 폴더를 자기 하위 폴더로 복사하는 작업, 링크·재분석 지점을 통한 전송은 거부합니다. 원격 전용 도구 모음 버튼은 로컬 탭에서 비활성화됩니다. 서버 탭으로 전환하면 오른쪽은 **원격 서버**로 바뀌며, 로컬 탭으로 돌아오면 오른쪽 로컬 경로·검색 필터·선택을 유지합니다. 양쪽의 이름 변경·새 폴더·삭제·텍스트 편집은 각각의 로컬 파일에 적용됩니다.

### 여러 파일과 폴더 선택하기

- 행의 **체크박스** 또는 `Ctrl` / `Cmd` 클릭으로 항목을 추가하거나 해제합니다. `Shift` 클릭은 현재 정렬 순서의 연속 범위를 선택합니다.
- 목록의 **빈 공간·크기·날짜 칸을 드래그**하면 박스로 선택합니다. 가장자리에 머물면 자동 스크롤합니다. `Shift` 드래그는 기존 선택에 추가하고 `Ctrl` / `Cmd` 드래그는 박스 안 항목의 선택을 반전합니다. 드래그 중 `Esc`는 시작 전 선택으로 되돌립니다.
- **파일 이름을 드래그**하면 선택된 파일·폴더들을 반대 패널로 전송합니다. 반대 패널의 폴더 위에 놓으면 해당 폴더가 목적지가 됩니다. 표시되는 전송 창에서 대상과 옵션을 확인하고 시작합니다.
- 선택된 행에서 **우클릭**하면 여러 항목의 선택을 유지한 채 작업 메뉴가 열립니다. 선택하지 않은 행을 우클릭하면 그 행만 선택합니다. `Shift+F10` 또는 패널 제목의 **…** 버튼도 같은 메뉴를 엽니다.
- 아래쪽에 선택 개수와 파일·폴더 구분, 전송·휴지통 버튼이 표시됩니다. **선택 항목 정보**에서 경로와 파일 용량을 확인할 수 있습니다. 용량은 폴더 내부를 합산하지 않습니다.

검색하면 표시되지 않는 항목은 선택에서 제외합니다. 같은 폴더 새로고침과 정렬은 남아 있는 항목의 선택을 유지하고, 다른 폴더나 서버로 이동하면 선택을 초기화합니다. 파일 목록에 키보드 포커스가 있을 때만 패널 테두리가 강조됩니다. `F2`·`F4`·`F5`·`F7`·`Delete` 파일 작업 단축키는 이 상태에서만 실행됩니다. 검색·경로 입력란, 상단 버튼, 메뉴·팝업이나 다른 프로그램으로 포커스를 옮기면 실행되지 않습니다. 입력란의 `Delete`는 평소처럼 글자를 지웁니다. 검색창 옆 **?** 버튼에서 선택 방법과 단축키를 확인할 수 있습니다.

작은 창에서는 **전송 큐 접기**로 목록 공간을 확보하세요. 높이 800px 미만에서 시작하면 큐를 접어서 표시합니다. 큐를 접어도 전송은 계속되며, 화살표나 사이드바 **전송 관리**로 다시 펼칠 수 있습니다.

상단의 **현재 경로 북마크** 아이콘으로 양쪽 경로를 함께 저장합니다. 북마크를 열 때 원격 경로는 **현재 연결한 서버**에서 열립니다. 북마크가 서버 연결까지 자동으로 바꾸지는 않습니다.

## 3. 첫 연결과 비밀번호 저장

### SFTP 서버에 연결하기

서버 관리자로부터 호스트, 포트, 계정, 인증 방법, SSH 호스트 키의 SHA256 지문을 준비합니다.

1. 왼쪽 메뉴의 **새 사이트** 또는 연결 탭 옆 **연결 탭 추가**(+)를 누르고 알아보기 쉬운 **사이트 이름**을 입력합니다.
2. **프로토콜**을 SFTP로 선택합니다.
3. **호스트 / S3 엔드포인트**에 `files.example.com`처럼 호스트 이름을 입력합니다. SFTP에는 `sftp://`나 폴더 경로를 붙이지 않습니다.
4. **포트**는 기본 포트를 사용하면 `0`, 별도 포트가 있으면 해당 번호를 입력합니다. SFTP 기본값은 22입니다.
5. **사용자 이름 / Access key**와 비밀번호를 입력합니다. 키 인증은 아래의 **SSH 키 · S3 고급 설정**에서 개인 키 파일 경로와 키 암호를 입력합니다.
6. **지문 확인**으로 읽은 SSH 지문을 관리자가 별도로 제공한 값과 비교합니다. 일치하는 지문을 사용합니다.
7. **로컬 시작 경로**와 **원격 시작 경로**를 지정합니다. 원격 경로가 확실하지 않으면 서버에서 허용하는 시작 경로를 관리자에게 확인합니다.
8. **이 사이트를 저장**을 선택하고 **연결**을 누릅니다. 연결 없이 설정만 보관하려면 **저장만**을 사용합니다.

사이트 연결·편집과 새 연결 창에서 입력란의 `Enter`는 **연결** 버튼과 같은 동작을 합니다. 한글 조합을 확정하는 Enter는 연결을 실행하지 않습니다. **저장만** 버튼은 설정만 저장하며, 연결·저장·지문 확인 오류는 토스트로 표시하고 입력한 값을 유지합니다. 오류를 수정한 뒤 다시 연결할 수 있습니다.

연결 후 오른쪽에 원격 목록이 표시되면 사용할 준비가 된 것입니다. 추가 인증 질문이나 일회용 코드가 필요한 서버에서는 **서버 인증** 창에 응답합니다.

### 암호화 Vault 사용하기

1. 사이드바 **설정 및 업데이트 → 암호화 Vault**를 엽니다.
2. 처음에는 12자 이상의 마스터 비밀번호를 입력하고 **Vault 생성**을 누릅니다.
3. 연결 설정에서 **비밀번호를 암호화 Vault에 저장**을 선택한 뒤 사이트를 저장합니다.
4. 운영체제 비밀 저장소에 접근할 수 있으면 다음 실행부터 Vault가 자동으로 열리고 저장된 사이트를 바로 연결할 수 있습니다. 비밀 저장소를 사용할 수 없다는 안내가 뜨면 다음 실행에서 마스터 비밀번호로 **잠금 해제**합니다.

**마스터 비밀번호를 잃으면 저장된 비밀을 복구할 수 없습니다.** 별도로 보관하세요. 개인 키 파일 자체는 Vault로 복사되지 않으므로 파일 경로와 파일을 유지해야 합니다. **Vault 잠금**은 자동 잠금 해제도 끄지만 이미 열린 서버 연결은 종료하지 않습니다. 다시 마스터 비밀번호로 열면 저장된 사이트의 자동 연결을 재설정합니다. 사이트에서 비밀번호 저장을 해제하면 해당 비밀이 삭제되고, 저장된 비밀이 하나도 없으면 자동 잠금 해제도 제거됩니다. 연결까지 끝내려면 연결 탭도 닫습니다.

## 4. 다른 연결 방식과 사이트 내보내기/가져오기

### 프로토콜별 입력

| 프로토콜 | 포트 0의 기본값 | 주로 입력할 내용 |
| --- | --- | --- |
| SFTP / SCP | 22 | 호스트, 계정, 비밀번호 또는 SSH 키, SSH 지문 |
| FTP / 명시적 FTPS | 21 | 호스트, 계정, 비밀번호, 필요한 FTP 데이터 모드 |
| 암시적 FTPS | 990 | 호스트, 계정, 비밀번호 |
| WebDAV / HTTPS WebDAV | 80 / 443 | 호스트, 계정, 비밀번호, WebDAV 폴더를 원격 시작 경로로 지정 |
| S3 | 443 | 엔드포인트, Access key, Secret key, 버킷, 리전, 필요시 세션 토큰 |

WebDAV의 호스트 칸에는 호스트 이름을 넣고 `/dav/files/user` 같은 경로는 **원격 시작 경로**에 넣습니다. S3 호환 서버의 별도 엔드포인트에는 서비스에서 제공한 URL을 사용할 수 있습니다. 버킷과 리전은 **SSH 키 · S3 고급 설정**에 있습니다. S3의 폴더는 객체 키의 접두사로 표시되며 Unix 권한이나 SSH 명령은 제공되지 않습니다.

**연결 · 인증 · 프록시**에서 인증 방식, 제한 시간, 연결 유지 간격, FTP 데이터 모드, HTTP/SOCKS 프록시를 설정합니다. 프록시와 인증 기능의 지원 범위는 프로토콜에 따라 다릅니다. SSH 경유 연결은 **SSH 점프 서버**에 별도 계정과 지문을 입력하며 한 단계만 지원합니다.

FTPS와 HTTPS는 기본적으로 시스템이 신뢰하는 인증서를 확인합니다. **TLS 인증서 · S3 · 사이트 메모**의 인증서 SHA256을 지정하면 그 인증서에 고정할 수 있습니다. 인증서 확인 결과는 서버 운영자가 제공한 값과 대조하세요. 인증서 조회는 직접 연결을 사용하므로 프록시로만 접근 가능한 서버에서는 조회가 실패할 수 있습니다.

### Portway 사이트 내보내기/가져오기

1. 사이드바의 **사이트 내보내기/가져오기**를 엽니다.
2. **내보내기**를 누르고 OS의 파일 저장 창에서 JSON 파일의 위치를 선택합니다. 파일을 선택하지 않아도 저장된 모든 사이트를 내보낼 수 있습니다. 저장 창을 취소하면 파일을 만들지 않습니다.
3. 다른 Portway에서 같은 메뉴를 열고 JSON 파일을 선택한 뒤 **가져오기**를 누릅니다. 기존 사이트는 유지하고 새 사이트로 추가하므로 같은 파일을 여러 번 가져오면 중복 사이트가 생깁니다.

Portway JSON은 S3와 프록시·점프 서버 등 고급 설정, 저장한 SSH/TLS 지문을 보존합니다. 비밀번호, 개인 키·인증서 암호, 인증 토큰과 파일 암호화 키는 제외합니다. Vault가 잠겨 있어도 내보낼 수 있으며 개인 키·인증서 파일 자체는 복사하지 않습니다. 개인 키·인증서와 로컬 경로는 새 컴퓨터에서 확인하고, 연결에 필요한 비밀은 다시 입력하세요. 파일 암호화를 사용한 사이트는 암호화 설정을 유지하므로 **기존 암호화 키를 다시 입력해야 연결할 수 있습니다**. 이 파일은 사이트 설정 이동용이며 Vault 전체 백업을 대신하지 않습니다.

가져오기 파일은 2 MiB 이하이며 한 번에 최대 1,000개 사이트를 처리합니다. 잘못된 사이트가 있으면 해당 가져오기를 전체 취소하고 기존 사이트를 유지합니다. 내보낼 사이트가 없으면 팝업에 안내합니다.

### WinSCP에서 옮겨오기

1. WinSCP에서 내보낸 INI 설정을 준비합니다.
2. 사이드바의 **사이트 내보내기/가져오기**를 열어 INI 파일을 선택하고 **가져오기**를 누릅니다.
3. 가져온 사이트의 호스트, 계정, 경로, 개인 키 경로를 확인합니다.
4. 비밀번호와 SSH 지문을 다시 설정한 뒤 연결합니다.

가져오기는 기본 사이트 정보만 옮깁니다. 저장 비밀번호와 모든 고급 설정은 이전되지 않으며 S3 항목은 건너뜁니다. 다른 OS로 이동한 경우 Windows 개인 키 경로 등을 해당 OS의 경로로 수정하세요.

## 5. 업로드·다운로드와 외부 드래그 앤 드롭

### 양쪽 패널에서 전송하기

1. 왼쪽을 사용할 로컬 폴더로, 오른쪽을 사용할 원격 폴더로 이동합니다.
2. 업로드는 왼쪽에서 선택하고 상단 버튼 그룹의 **업로드**, 다운로드는 오른쪽에서 선택하고 **다운로드**를 누릅니다. 선택 항목을 반대 패널로 드래그해도 됩니다.
3. 대화상자에서 **대상 폴더**와 **같은 이름의 파일** 정책을 확인합니다.
4. **전송 시작**을 누른 뒤 아래쪽 큐에서 완료 여부를 확인합니다.

| 같은 이름의 파일 | 동작 |
| --- | --- |
| 건너뛰기 | 대상에 이미 있는 파일은 건너뜁니다. 기본 선택입니다 |
| 덮어쓰기 | 대상 파일을 전송한 파일로 교체합니다 |
| 더 최신 파일만 | 원본이 더 최신인 경우에 전송합니다 |
| 다른 이름으로 보관 | 대상의 기존 파일을 유지할 수 있도록 다른 이름으로 전송합니다 |

폴더는 하위 항목까지 처리합니다. 재귀 전송에서 심볼릭 링크를 따라가지는 않습니다. 파일 수나 용량만 보지 말고 큐의 **완료/실패** 상태를 확인하세요.

### 탐색기·Finder·Linux 파일 관리자에서 가져오기

1. Portway에서 서버에 연결하고 **오른쪽 원격 패널**을 목적지 폴더로 이동합니다.
2. 외부 파일 관리자에서 파일이나 폴더 여러 개를 선택합니다.
3. 선택 항목을 Portway의 **오른쪽 원격 패널**에 놓습니다.
4. 확인 창의 파일·폴더 수, 용량, 대상 서버·폴더와 충돌 정책을 확인하고 전송합니다.
5. 로컬 준비가 끝나면 전송 큐에 추가됩니다. 큐에서 서버 전송이 완료됐는지 확인합니다.

목적지는 **놓는 순간의 연결과 원격 경로**입니다. 왼쪽 패널의 경로와 관계없이 전송하며 원본 파일은 유지합니다. 준비 중 취소할 수 있고, 큐에 들어간 뒤에는 큐의 일시정지·취소를 사용합니다.

드롭 대신 상단 **외부 파일** 또는 **외부 폴더**를 눌러 선택할 수도 있습니다. 폴더 선택 방식은 브라우저 제약으로 빈 폴더를 전달하지 못할 수 있습니다. 드롭 방식은 중첩 폴더와 빈 폴더를 보존하도록 구현되어 있습니다.

외부 전송은 앱 데이터 위치에 임시 사본을 만들므로 선택한 전체 용량과 여유 공간이 필요합니다. 원본의 OS 권한·ACL·확장 속성을 그대로 복제하는 기능은 아닙니다. 한 번에 최대 20,000개 파일·폴더 항목과 깊이 64를 처리하며, 제한을 넘으면 묶음을 나눠 전송합니다.

현재 실제 파일을 사용하는 Chromium 드롭과 SFTP 도착 파일 검증은 완료했습니다. **Explorer/Finder/Linux 파일 관리자에서 Photino 네이티브 창으로 놓는 실제 OS 제스처는 아직 검증하지 않았습니다.** 환경에서 드롭이 동작하지 않으면 선택 버튼이나 왼쪽 패널 업로드를 사용하세요. 원격 파일을 외부 파일 관리자로 끌어내는 기능은 아직 없으므로 **다운로드**를 사용합니다.

## 6. 전송 옵션과 중단한 작업 재개

전송 창의 **전송 필터 · 검증 · 프리셋**을 펼치면 다음 옵션을 사용할 수 있습니다.

| 옵션 | 사용 방법 |
| --- | --- |
| 파일 마스크 | 포함할 파일과 제외할 파일을 패턴으로 지정합니다. 아래 예시를 참고하세요 |
| 전송 모드 | 기본 **바이너리 · 그대로**는 내용을 바꾸지 않습니다. 텍스트 모드는 줄바꿈을 변환하며 자동 모드는 텍스트 마스크로 선택합니다 |
| 수정 시각·읽기 전용·업로드 권한 | 서버와 프로토콜이 지원하는 속성을 적용합니다 |
| 숨김 파일·빈 폴더 제외 | 필요 없는 항목을 전송 대상에서 제외합니다 |
| 전송 후 SHA256 검증 | 전송 결과의 내용을 검증합니다. 추가 읽기와 네트워크 시간이 들 수 있습니다 |
| 이어받기·자동 재시도 | 지원되는 전송에서 중단 지점을 활용하고 연결 오류를 재시도합니다 |
| 우선순위·예약 실행 | 우선순위는 -10~10이며 높은 값을 먼저 처리합니다. 예약 시간에는 앱이 실행 중이어야 합니다 |
| 전송 성공 후 원본 삭제 (이동) | 일반 패널 전송에서 원본 삭제를 요청합니다. 외부 파일 드롭은 원본을 유지합니다 |

파일 마스크 `*.txt;*.csv|*.bak`는 txt/csv를 포함하고 bak를 제외합니다. `;`로 여러 패턴, `|`로 포함/제외를 나눕니다. WinSCP 문법 전체와 같지는 않습니다. 반복해서 쓰는 옵션은 **현재 설정을 프리셋으로 저장**합니다. 속도 제한은 전송 창의 KB/s 값으로 지정하며 `0`은 제한 없음입니다. **설정 및 업데이트 → 동시 전송 수**는 1~8 사이에서 지정합니다.

### 멈추거나 실패한 전송

- **일시정지**: 진행 중 작업을 멈추고 나중에 재개합니다.
- **취소**: 현재 작업을 중단합니다. 이미 대상에 도착한 파일이나 일부 내용까지 되돌리지는 않습니다.
- **이어하기 / 재시도**: 일시정지·실패·취소된 작업을 다시 실행합니다. 오류가 권한이나 경로 문제라면 원인을 먼저 해결합니다.
- **앱 재시작 후**: 작업은 일시정지 상태로 복원됩니다. Vault를 잠금 해제하고 원래와 같은 서버·계정·지문으로 연결한 후 재시도합니다.

전송 진행 용량은 현재 처리하는 파일 기준일 수 있습니다. 폴더 전체의 합계와 다를 수 있고 마지막 파일이 빈 파일이면 `0 B / 0 B`가 보일 수 있습니다.

외부 드롭의 실패·취소·일시정지 작업은 재시도할 수 있도록 임시 사본이 남습니다. **기록 정리**는 완료·실패·취소 상태의 기록을 함께 제거합니다. 재시도할 실패·취소 작업이 남아 있으면 먼저 재시도하세요. 작업 기록이나 앱 데이터의 `drops` 폴더를 먼저 지우지 마세요.

## 7. 파일 관리와 휴지통 복원

목록의 우클릭 메뉴 또는 패널 제목 옆 **… 파일 작업** 버튼에서 새 폴더, 이름 변경, 텍스트 편집, 삭제, SHA256 체크섬을 사용할 수 있습니다. 원격 패널에는 원격 복사, 링크 생성, 속성·폴더 크기, 하위 폴더 검색, 권한·소유자 메뉴도 있습니다. 서버나 프로토콜이 지원하지 않는 작업은 오류로 안내됩니다.

**전송·이동·휴지통·영구 삭제**는 선택한 파일과 폴더 모두에 적용합니다. **SHA256 체크섬**은 여러 파일의 결과를 각각 표시하고, 원격 **권한 · 소유자**는 여러 파일·폴더에 같은 설정을 적용합니다. 이름 변경·편집·서버 내 복사·링크 생성은 항목 하나를 선택합니다. 지원하지 않거나 선택 조건이 맞지 않는 메뉴는 비활성화합니다. 여러 항목 처리 중 오류가 발생하면 완료한 개수와 오류를 표시합니다. 완료된 작업을 일괄 취소하지는 않습니다.

**권한 · 소유자**는 `755` 같은 8진수 권한과 숫자 UID/GID를 사용합니다. **하위 폴더와 파일에 적용**을 선택하면 재귀 적용되므로 대상 폴더를 확인하세요. **원격 복사**는 새 절대 경로를 입력합니다. 서버 내부 복사를 제공하지 않는 프로토콜에서는 클라이언트를 거쳐 복사할 수 있습니다.

### 삭제한 항목 복원하기

1. 파일을 선택하고 `Delete` 또는 **휴지통으로 이동**을 사용합니다.
2. 복원이 필요하면 사이드바 **휴지통 복원**을 엽니다.
3. 원격 항목이면 원래 서버에 먼저 연결합니다.
4. 해당 항목의 **원래 위치로 복원**을 누릅니다.

Portway 휴지통은 원본 부모 폴더의 `.portway-trash`에 보관합니다. **Windows 휴지통이나 macOS 휴지통과 별개**이며 원본과 같은 디스크 또는 서버의 공간을 사용합니다. 원래 위치에 같은 이름이 있으면 복원이 거부됩니다. 기존 항목을 확인하고 이름을 바꾸거나 다른 곳에 보관한 뒤 복원하세요.

**영구 삭제**와 동기화의 삭제 작업은 이 휴지통을 거치지 않습니다.

<a id="edit"></a>
## 8. 파일 편집

### 내부 텍스트 편집기

파일 하나를 선택하고 `F4` 또는 **텍스트 편집**을 누릅니다. 내용을 수정한 뒤 **저장** 또는 `Ctrl+S` / `Cmd+S`를 누릅니다. 저장 인코딩과 BOM을 선택할 수 있습니다. UTF-8, UTF-16/32, cp949 등을 지원하며 내부 편집 한도는 16 MiB입니다.

편집기는 앱에 포함된 **Monaco Editor**로 인터넷 연결 없이 동작합니다. 파일 확장자에 따라 구문을 강조하며, 위쪽 **언어** 메뉴에서 직접 바꿀 수도 있습니다. **찾기** 또는 `Ctrl+F` / `Cmd+F`로 검색하고 검색 창의 화살표를 펼쳐 바꿀 문자열을 입력합니다. **줄바꿈**은 화면의 긴 줄만 접으며 파일 내용은 바꾸지 않습니다. `F1`은 편집 명령 팔레트를 엽니다. 줄 번호, 현재 줄·열, LF/CRLF 상태도 표시됩니다. 찾기 창 안의 `Esc`는 찾기를 닫습니다.

파일명 옆 점과 **저장하지 않은 변경 내용**은 저장이 필요한 상태를 뜻합니다. 인코딩이나 BOM만 바꿔도 표시됩니다. 저장 중 입력한 내용은 해당 요청에 포함되지 않으므로 저장 완료 뒤 다시 저장해야 합니다. 인코딩을 자동으로 읽지 못하면 **파일 읽기 및 인코딩** 창에 `cp949` 등 실제 인코딩을 입력하세요. 기존 줄바꿈은 유지하며, 혼합된 줄바꿈은 내용을 편집하여 저장할 때 Monaco가 감지한 방식으로 통일될 수 있습니다.

편집 중 원본이 다른 곳에서 바뀌면 저장 충돌이 발생할 수 있습니다. 작성 중인 내용을 별도로 보관한 뒤 최신 파일을 다시 열어 비교하세요. 저장되지 않은 상태로 창을 닫으면 변경 내용을 버릴지 확인합니다.

### 외부 편집기와 자동 업로드

1. **설정 및 업데이트 → 외부 편집기 실행 파일**에 편집기의 실제 실행 파일 경로를 넣습니다.
2. **편집기 인수 (JSON 배열)**에 인수를 지정합니다. 기본값은 `["{file}"]`입니다. 각 인수는 별도 문자열로 넣고 파일 경로를 직접 붙이지 않습니다.
3. 원격 파일 하나를 선택하고 파일 메뉴의 **외부 편집기**를 실행합니다.
4. 편집기에서 저장하면 변경을 감지해 서버에 업로드합니다.
5. 작업 후 사이드바 **외부 편집 세션 → 자동 저장 종료**를 누릅니다.

충돌이 발생하면 자동 덮어쓰기를 멈추고 로컬 복구 사본을 유지합니다. **외부 편집 세션**에서 사본 경로와 오류를 확인할 수 있습니다. 서버의 최신 파일과 비교한 뒤 의도한 경우에만 **로컬 사본으로 서버 덮어쓰기**를 사용합니다. 자동 저장을 종료해도 복구 사본은 남습니다.

<a id="sync"></a>
## 9. 폴더 동기화

### 변경 내용을 확인하고 한 번 실행하기

1. 양쪽 패널을 비교할 폴더로 이동하고 **동기화**를 누릅니다.
2. 로컬·원격 경로와 **로컬 → 원격**, **원격 → 로컬**, **양방향 · 최신 파일 기준** 중 방향을 선택합니다.
3. 필요한 전송 필터를 지정하고 미리보기를 실행합니다. 내용 비교를 위해 원격 파일을 읽을 수 있으므로 큰 폴더는 시간이 걸립니다.
4. 변경 목록에서 실행할 항목만 선택합니다. 충돌 항목은 **건너뛰기 / 로컬 사용 / 원격 사용**으로 처리 방향을 정합니다.
5. 적용 후 하단 상태 표시와 완료·오류 안내를 확인합니다.

**대상에만 있는 파일 삭제 (단방향만)**를 켜면 대상의 추가 항목이 영구 삭제 대상에 들어갑니다. 미리보기의 삭제 목록을 확인하세요. 양방향 최신 파일 비교는 편집 이력을 추적하는 버전 관리가 아닙니다. 미리보기 후 파일이 변경되어 실행이 거부되면 다시 비교합니다. 여러 파일에 대한 작업 전체를 한 번에 되돌리는 기능은 없습니다.

### 지속 동기화

**지속 동기화**에서 폴더, 단방향, 확인 간격과 옵션을 정하고 **새 감시 시작**을 누릅니다. 로컬 변경 감지와 주기적 서버 비교를 함께 사용합니다. 앱이 실행 중이고 서버에 접근할 수 있어야 합니다.

등록된 감시에서 **일시정지**, **재개**, **등록 해제**를 사용할 수 있습니다. 앱 재시작 후에는 원래 서버에 다시 연결하고 감시를 재개합니다. 현재 지속 동기화는 **단방향**이며 양방향 감시는 제공하지 않습니다.

## 10. SSH 터미널과 파일 암호화

### SSH 작업

SSH 서버에 연결한 뒤 상단 **SSH 명령** 아이콘을 누르면 대화형 터미널을 엽니다. 명령 입력, 창 크기 변경, `Ctrl+C`를 지원합니다. 창의 **연결 종료**로 터미널을 닫습니다.

터미널에 포커스가 있을 때 커서는 표시와 숨김을 1초마다 전환합니다. OS의 모션 줄이기 설정이 켜져 있어도 같은 간격을 유지합니다.

반복 명령은 **설정 및 업데이트 → SSH 사용자 명령 (JSON 배열)**에 등록하고 원격 파일 메뉴의 **사용자 명령**에서 실행합니다. 예를 들어 서버에 `sha256sum`이 있는 경우:

```json
[{"name":"SHA256","template":"sha256sum -- {files}","remote":true}]
```

`{file}`, `{files}`, `{directory}`는 선택 파일과 현재 원격 경로로 치환됩니다. 경로의 따옴표 처리는 앱이 수행하므로 플레이스홀더에 따옴표를 다시 씌우지 않습니다. 명령은 연결된 서버에서 실행되며 서버 계정의 권한으로 실제 파일을 바꿀 수 있습니다. CLI를 통한 반복 작업은 [자동화 가이드](AUTOMATION.md)를 참고하세요.

### SFTP 파일 이름·내용 암호화

연결 설정의 **SFTP 파일 암호화 · WinSCP 호환**을 펼치고 **파일 이름과 내용을 암호화**를 선택합니다. 기존 WinSCP의 64자리 16진수 키를 입력하거나 **새 키 생성**을 사용합니다. 이 키는 Vault의 마스터 비밀번호와 별개이며 **원본 키를 별도로 백업**해야 합니다.

새 암호화 파일을 쓰고 읽을 수 있지만 기존 평문 파일 전체를 자동 변환하지는 않습니다. 호환 형식은 AES-CTR이고 변조 인증 태그가 없습니다. 암호화 파일의 중단 전송은 처음부터 재전송합니다. 암호화 세션에서 터미널을 사용하려면 파일 암호화를 끈 별도 SSH 연결을 사용합니다.

## 12. 업데이트와 백업

### 자동 업데이트

피드 URL을 한 번 저장하면 **앱을 시작할 때마다** 백그라운드에서 업데이트를 확인하고 새 버전을 다운로드합니다. 다운로드가 완료되어도 현재 작업을 중단하거나 앱을 즉시 재시작하지 않습니다. 앱을 완전히 종료한 뒤 **다음 실행 시**, 창과 파일 작업을 시작하기 전에 준비된 버전을 사용자 조작 없이 적용합니다.

1. 배포 운영자에게 받은 OS·아키텍처·채널별 피드 디렉터리 URL을 **설정 및 업데이트 → 배포 서버 피드 URL**에 입력하고 **설정 저장**을 누릅니다.
2. 다음에 앱을 실행하면 자동으로 확인·다운로드합니다. 처음 URL을 저장한 실행에서는 **업데이트 확인**을 눌러 바로 시작할 수도 있습니다.
3. 설정 화면에서 확인 중, 다운로드 진행률, **다음 실행 시 자동 적용** 상태를 볼 수 있습니다.
4. 평소처럼 작업을 마치고 앱을 종료합니다. 다음에 실행하면 준비한 새 버전으로 시작합니다.

네트워크나 다운로드 오류가 있어도 앱은 계속 사용할 수 있습니다. 다음 실행 또는 수동 확인으로 다시 시도합니다. 다운로드가 완전히 끝나 검증된 패키지만 적용 대상이 됩니다. 준비가 끝난 업데이트는 서버 연결이 끊겨도 다음 실행에 적용할 수 있습니다. URL을 비우면 이후 자동 확인은 생략하지만 **이미 다운로드한 업데이트의 다음 실행 시 적용까지 취소하지는 않습니다.**

### 수동 업데이트

1. 배포 운영자로부터 자신의 OS·아키텍처·채널에 맞는 **피드 디렉터리 URL**을 받습니다. 예: `https://downloads.example.com/releases/win-x64-stable/`.
2. **설정 및 업데이트 → 배포 서버 피드 URL**에 입력합니다. 배포 서버 첫 화면이나 설치 파일 URL을 넣지 않습니다.
3. **업데이트 확인 → 다운로드**를 실행합니다.
4. 전송과 동기화를 멈추고 외부 편집 세션을 종료한 뒤 **적용 후 재시작**을 누릅니다.
5. 재실행 후 버전과 저장된 설정을 확인합니다.

공개 배포 서버는 HTTPS를 사용합니다. 설치된 Velopack 패키지 기준의 기능이며 소스 실행에서는 업데이트 설치를 사용할 수 없습니다. 일반 사용자의 업데이트에 관리자 게시 키는 필요하지 않습니다.

### 데이터 백업

설정은 OS의 사용자별 로컬 앱 데이터 위치 아래 `Portway` 폴더에 저장됩니다. Windows 기본값은 `%LOCALAPPDATA%\Portway`입니다. 개발자가 `Portway__DataPath`를 지정했다면 그 위치를 사용합니다. macOS/Linux에서는 .NET의 `LocalApplicationData` 위치를 기준으로 하므로 설치 환경의 실제 경로를 확인하세요.

앱과 작업을 종료한 뒤 프로필 폴더 전체를 함께 백업합니다. `sites.json`과 `vault.json`은 함께 보관하고 마스터 비밀번호도 별도로 유지합니다. 자동 잠금 해제 정보인 `vault-auto.json`은 현재 운영체제 사용자에게 묶이므로 다른 컴퓨터에서 복원한 뒤에는 마스터 비밀번호로 잠금 해제하세요. `preferences.json`에는 북마크·테마·작업 설정 등이 있습니다. 전송을 나중에 재개하려면 `queue`와 `drops`, 편집 복구를 위해서는 `editor` 폴더도 보존합니다.

개인 키·클라이언트 인증서·일반 전송 원본·원격 파일은 프로필에 포함되지 않으므로 별도로 백업해야 합니다. 휴지통의 실제 파일은 각 원본 부모의 `.portway-trash`에 있으며 프로필에는 복원 기록이 들어 있습니다. 새 컴퓨터에 프로필을 복원한 경우 키 파일과 로컬 폴더 경로가 유효한지 먼저 확인하세요.

<a id="troubleshooting"></a>
## 13. 문제 해결과 지원 범위

| 증상 | 확인할 내용 |
| --- | --- |
| SSH 지문이 없거나 일치하지 않음 | 서버 관리자에게 현재 지문을 확인합니다. 서버 변경을 확인하기 전에 새 지문으로 바꾸지 않습니다 |
| 저장된 비밀번호를 사용할 수 없음 | Vault를 잠금 해제합니다. 저장하지 않은 비밀번호는 연결할 때 다시 입력합니다 |
| 연결은 되지만 업로드가 실패함 | 원격 폴더 쓰기 권한, 서버 여유 공간, 파일 이름과 오류 문구를 확인합니다 |
| 외부 드롭 준비가 실패함 | 로컬 여유 공간, 읽을 수 있는 파일인지, 이름 중복·깊이·항목 수를 확인합니다. 파일 선택 또는 패널 업로드로 재시도합니다 |
| 재시도 시 다른 서버라는 안내 | 원래의 호스트·포트·계정·프로토콜·지문에 맞는 연결 탭을 선택합니다 |
| 파일이 누락된 것처럼 보임 | 목록 필터·숨김 표시·전송 마스크·충돌 정책의 건너뛰기 여부를 확인합니다 |
| 편집 또는 동기화 충돌 | 작성본을 보관하고 최신 원본과 다시 비교합니다. 내용 확인 후 처리 방향을 선택합니다 |
| 휴지통 복원이 실패함 | 원래 서버에 연결했는지, 실제 휴지통 파일이 남아 있는지, 원래 이름이 이미 존재하는지 확인합니다 |
| 업데이트가 비활성화되거나 실패함 | 설치 패키지로 실행했는지, 피드 URL의 RID/채널, 진행 중 작업과 오류 문구를 확인합니다 |
| Linux 창이 열리지 않음 | 그래픽 세션과 GTK/WebKitGTK/libnotify 설치 여부를 확인합니다. FUSE 오류이면 추출 실행 방식을 사용합니다 |
| Windows Debug 창이 검은 화면으로 멈춤 | 현재 개발 소스는 다른 Photino 앱과 충돌하지 않도록 Portway 전용 `webview` 폴더를 사용합니다. Visual Studio에서 디버깅을 종료하고 최신 소스를 Debug로 다시 빌드·실행합니다. 사이트·Vault·큐 또는 다른 앱의 공용 브라우저 폴더를 삭제할 필요는 없습니다 |

문제를 전달할 때 OS·CPU 아키텍처, Portway 버전, 프로토콜, 수행 순서, 비밀 값을 제거한 오류 문구를 함께 기록하면 재현에 도움이 됩니다. 비밀번호·키·토큰과 개인 파일 내용은 공유하지 않습니다.

Portway 0.3.9는 **WinSCP의 모든 기능을 완전히 대체하는 단계는 아닙니다.** OS 셸 통합, 외부로 드래그 다운로드, GSSAPI/SSH agent forwarding, WinSCP 스크립트·COM·.NET 바이너리 전체 호환 등에는 차이가 있습니다. 실제 Mac 실행, 모든 OS의 네이티브 드롭, 일부 인증 방식도 추가 검증이 필요합니다. 자세한 범위는 [기능별 대체 검증표](PARITY.md), 기존 프로토콜 검증은 [0.3.1 보고서](../jobs/VALIDATION-0.3.1.md), 다중 선택·파일 관리 검증은 [0.3.5 보고서](../jobs/VALIDATION-0.3.5.md), Monaco·팝업 검증은 [0.3.4 보고서](../jobs/VALIDATION-0.3.4.md), 자동 업데이트 검증은 [0.3.3 보고서](../jobs/VALIDATION-0.3.3.md)에 있습니다.
