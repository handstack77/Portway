# Portway 현재 구현 복원 문서

Portway의 개발 소스를 기획·관리 검토 관점에서 역으로 분석한 문서입니다. 제품의 기능과 제약, 사용자 흐름, 설계와 시스템 경계를 설명합니다. 원래 작성된 기획서나 승인된 사업 계획을 복원한 것으로 간주하지 않습니다.

| 4 | [아키텍처](ARCHITECTURE.md) | 프로젝트·실행·배포 경계와 보안·복구 책임은 어디에 있는가 |

처음에는 기획서와 분석서의 검증 수준을 읽고, 구체적인 동작이나 책임을 확인할 때 설계서·아키텍처로 이동하세요. 개발자의 상세 탐색은 기존 [소스 탐색 가이드](../SOURCE-MAP.md), [솔루션 구조](../ARCHITECTURE.md), [API 목록](../API-REFERENCE.md)을 사용합니다.

## 핵심 결과

- Desktop은 로컬 웹 UI를 Photino 창에 표시하고, 인증된 loopback API를 통해 파일 작업을 실행합니다. 일반 공개 웹 파일 관리 서비스로 구성되어 있지 않습니다.
- Core는 실제 로컬·원격 파일 처리와 자동화의 중심입니다. CLI는 Core를 직접 사용하며 Desktop 실행이 필요하지 않습니다.
- Server는 업데이트 패키지 게시·다운로드를 담당합니다. 사용자 파일의 업로드·다운로드는 클라이언트에서 원격 서버로 직접 이루어집니다.
- 로컬 작업 공간은 서버 없이 양쪽 로컬 폴더를 다룹니다. 전송 큐와 지속 동기화 등록은 재시작 후 자동 실행하지 않고 일시정지 상태로 복원합니다.
- 자동 업데이트는 실행 중 확인·다운로드한 뒤 다음 시작에 적용합니다. 수동 적용은 활성 파일 작업을 검사합니다.
- 프로토콜별 기능은 capability와 실제 서버 조건에 따라 달라집니다. Windows·macOS·Linux 대상 구성이 있다는 사실이 모든 OS의 네이티브 검증 완료를 뜻하지 않습니다.

근거는 [요구사항 추적표](ANALYSIS.md#traceability)와 [아키텍처의 설계 선택](ARCHITECTURE.md#decisions)에 연결했습니다.

## 근거 표시와 확인 한계

| 표시 | 의미 |
| --- | --- |
| 구현 확인 | 현재 소스에서 처리 경로·조건을 확인함. 실행 성공을 뜻하지 않음 |
| 추론 | 코드와 사용 흐름에서 제품 의도·사용자 요구를 해석함. 직접적인 기획 근거가 없음 |
| 기존 검증 기록 | 이전 보고서의 결과. 당시 소스·빌드·환경에 한정 |
| 이번 실행 확인 | 이번 작업에서 직접 실행한 문서 검사 결과 |
| 미확인 | 근거 또는 실행 환경이 부족해 확정할 수 없음 |

아래 문서의 동작 설명은 별도 표시가 없으면 **구현 확인**입니다. 사용자 유형·제품 가치와 설계의 기대 효과는 **추론**으로 표시했습니다. 테스트 링크는 검사 항목의 존재와 의도를 보여 주며, 통과 증거는 연결한 검증 기록을 별도로 확인해야 합니다.

이번에는 문서 프로젝트 구문 검사, 새 문서·안내 링크 검사, 요구사항 ID와 근거 경로 확인, Mermaid 도식 검사를 수행합니다. 실제 완료 결과는 [이번 문서 검증 기록](../../jobs/VALIDATION-reverse-engineering-20260929.md)에 기록합니다. 앱 실행, .NET 기능 테스트, 실제 프로토콜 연결, 설치·업데이트와 OS별 네이티브 UI 검사는 이번 작업에서 재실행하지 않습니다.

미확인 사항은 원래 제품 기획·시장 지표·실사용자 수·성능 SLA, 모든 서버 구현과의 호환성, 전체 OS 최소 버전, macOS 실기기 설치·서명·공증입니다. 기존 검증의 세부 한계는 [분석서](ANALYSIS.md#verification)를 참고하세요.
